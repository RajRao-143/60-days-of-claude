# 30-Day Growth Plan — LaunchPath AI

A practical post-v1.0.0 plan focused on reliability and polish. Aim for 30–60 minutes per day; move a task if the previous one exposes a bug.

| Day | Task | Deliverable |
|---|---|---|
| 1 | Create a release test checklist | `qa-checklist.md` |
| 2 | Inspect all tabs on desktop | Desktop test notes |
| 3 | Test roadmap completion and notes persistence | Result notes |
| 4 | Test resource filters and tutor flow | Result notes |
| 5 | Test aptitude answer/check/next flow | Result notes |
| 6 | Test coding hints, solution reveal and self-practice | Result notes |
| 7 | Test interview presets, saving and finish-now | Result notes |
| 8 | Test job create, edit, delete and required fields | Result notes |
| 9 | Test filters, search, dates and reminders | Result notes |
| 10 | Compare analytics against known sample activity | Metric verification |
| 11 | Test print preview and save analytics as PDF | PDF evidence |
| 12 | Test at 360px mobile width | Mobile screenshots |
| 13 | Test at tablet width | Tablet screenshots |
| 14 | Fix the highest-impact verified mobile issue | Fix commit |
| 15 | Check keyboard navigation and focus visibility | Accessibility notes |
| 16 | Check labels, headings and contrast | Accessibility notes |
| 17 | Test empty states and invalid form inputs | Validation notes |
| 18 | Test reload persistence and malformed storage recovery | Data test notes |
| 19 | Review privacy and data-loss messaging | Updated copy |
| 20 | Add a first-run guide | Help section or guide |
| 21 | Review resource links and relevance | Updated resource list |
| 22 | Ask two students to try the main workflow | Feedback notes |
| 23 | Prioritise feedback by severity and frequency | Issue list |
| 24 | Fix one high-priority issue | Fix commit |
| 25 | Update README screenshots and run instructions | README update |
| 26 | Add a changelog entry | `CHANGELOG.md` |
| 27 | Re-run the smoke checklist | QA summary |
| 28 | Record a short product demo | Demo file/link |
| 29 | Review open issues and defer low-value features | Backlog |
| 30 | Publish a maintenance release if fixes are verified | Release notes |

## Rules
- Do not add features just to increase feature count.
- Keep a screenshot or note for each completed QA task.
- Never present fictional jobs as real opportunities.
- Do not mark tests passed until performed.
- Preserve existing localStorage keys unless a safe migration is tested.
