# Future Scope — LaunchPath AI

**Project:** LaunchPath AI — Your Intelligent Placement Readiness Companion  
**Release target:** v1.0.0  
**Current implementation:** Standalone HTML, CSS and JavaScript; browser localStorage; GitHub Pages.

## Next 3 months — Stabilise the MVP
- Run and document a module-by-module test pass on desktop and mobile.
- Fix verified usability, accessibility and validation issues before adding features.
- Add clear empty states, error messages and a first-run guide.
- Test localStorage persistence, malformed-data handling and print-to-PDF behaviour.
- Explain browser-local storage and data-loss limitations clearly.
- Add automated smoke checks for navigation, core forms and analytics where practical.
- Collect feedback from a small group of students.

**Evidence:** QA checklist, mobile/desktop screenshots, resolved issue list and feedback notes.

## Next 6 months — Improve usefulness
- Add optional JSON backup/restore with schema validation and confirmation.
- Add configurable weekly goals and progress summaries without predicting placement probability.
- Review resource links and show source/freshness information.
- Explain analytics metrics and continue excluding demo records from real application counts.
- Improve keyboard navigation, focus states, semantic labels and contrast.
- Consider a backend only if cross-device sync is a real user need; assess privacy and security first.

**Evidence:** tested backup/restore, accessibility review and user feedback.

## Next 12 months — Responsible expansion
- Consider opt-in account sync only after a threat model, consent flow and data export/deletion plan.
- Explore optional AI feedback with transparent limitations and a deterministic fallback.
- Add curated job links only with source attribution and freshness checks.
- Build role-specific learning paths from reviewed skill frameworks.
- Establish versioned releases, issue templates, changelog entries and regression tests.

**Evidence:** privacy review, release notes, verified data-source policy and measurable usability improvements.

## Product guardrails
1. Readiness indicators are preparation signals, not placement odds.
2. Never fabricate jobs, deadlines, user activity or analytics.
3. Keep demo data visibly labelled and exclude it from genuine application totals.
4. Explain where data is stored and what happens when browser data is cleared.
5. AI assistance must be optional, transparent and have a fallback.
6. Do not collect sensitive student information without a clear need and consent.
